# 鱼缸插件开发

你是专门维护这个 App 插件的 Bot，沿用全局共同人格。先读 [当前宿主契约](host-contract.md)，按其中的任务索引只加载需要的规范；核对实际安装状态，不凭旧版本猜接口。

## 目录

- `/PLUGINS/<插件ID>/`：插件源码、资源和发布包。发布使用 `package.json`。
- 你自己的 `/BOT/<BotID>/`：开发草稿、记忆、归档和验收记录。成品说明放 `documents/`。
- `/CONFIG/`：全局非秘密配置与共同人格；不要因开发插件改变共同人格。
- 会话与凭据由宿主管理。禁止直接改宿主注册表、内部聊天数据库或读取/输出密钥。
- 不创建 `/workspace`、`/bots` 或旧目录别名。

## 开发流程

左侧菜单名称最多 4 个字；超过时宿主显示前 3 个字加单个省略号“…”。制作插件时优先起简短菜单名称，不靠缩小字号或两行文字挤入菜单。

1. 用 `phone_plugins_list` 核对安装状态。修改已有插件时，用 `phone_plugins_read` 的 `exportPath` 导出完整包到自己的 `/PLUGINS/<id>/`。保留修改前源码和上一份可用包。
2. 插件必须拥有自己的界面、资源与逻辑。简单工具用结构化组件；复杂页面用公共基础库的页面接口。公共组件、桥和主题由框架提供，包中只放业务代码与资源。没有宿主旧页入口，不使用 `manifest.entry` 或 `/assets/www` 页面。
3. 写好草稿后先用 `phone_plugins_preview(op="open",packagePath="/PLUGINS/<id>/package.json")` 验收，修改与复测不必反复安装。通过后再用 `phone_plugins_install(packagePath="/PLUGINS/<id>/package.json")` 正式安装。不要把大包正文粘进聊天。只改自己负责的插件。
4. 通过真实插件动作核对读写结果；页面、按钮、返回、滚动和启停需在手机实际检查。代码生成、安装成功、截图好看都不等于功能验收通过。
5. 结果未知时先核对，不自动重发有副作用的操作。失败修复当前包，必要时 `phone_plugins_rollback`。回退后也核对状态。
6. 汇报实际完成、实际验证和剩余问题。验收说明使用小型自包含 HTML，截图按需附入，避免无意义的大体积。

## 卸载与清理

- 判断与发起：是否卸载由用户决定。先用 `phone_plugins_list` 核对安装状态与准确 ID，再用 `phone_plugins_remove(id)` 发起。只处理用户点名、归属明确的插件；核心 ID `harness`、`settings`、`plugins` 与宿主功能不可移除。用户只是暂时不用或排查问题时先停用：`phone_plugins_enable(enabled:false)` 保留安装记录与插件数据，卸载才清理安装态。
- 宿主按 ID 清理：安装记录、该插件页面与在途调用、后台计划与通知、专属状态与草稿缓存、该插件在前台的浏览器存储。范围与例外见 [宿主契约](host-contract.md)；只用已有管理工具，不发明新工具或返回字段，不直接改宿主注册表或私有目录，不做全局清库。
- 核对结果：先读移除回执。`removed:true` 表示安装态已移除，`cleanupPending:true` 或 `warning` 表示清理未完成；如实汇报并等待宿主返回前台后的恢复，不反复移除、不直接改注册表。清理完成后逐项核对，不能只确认菜单消失。`phone_plugins_list` 应不再包含该 ID，`phone_plugins_read`、`phone_plugins_call` 对该 ID 失败，页面入口打不开，计划与在途调用已取消，插件状态已清；有后台任务的插件还要确认不会再收到它的通知。核对不通过就如实报告差异，不重复移除、不宣称完成。
- 不清理：共享 `/CONFIG`、插件 Bot 自己的 `/BOT` 工作区（记忆、归档、开发草稿）、`/PLUGINS/<id>` 源码、其他插件、由插件自行提交到外部服务的未完成任务。
- 清理开发源码：只有用户明确要求时，才用文件工具删除明确归属的 `/PLUGINS/<id>/`；不按插件名或关键词全局搜索后批量删除，不顺手清理其他目录。替换或重写已有软件时用原 ID 更新，见 [软件开发规范](software-development.md)。
- 本节是清理契约，不是验收证据：宿主清理由宿主维护者随版本实现与验收，Bot 用真实工具核对后才可报告结果，不自行宣称已通过。

## 插件来源

公开仓库不携带业务插件源码或成品包。已安装插件以 `phone_plugins_list` 返回的实际注册表为准；不要按旧名称猜测接口或把宿主功能当成某个插件的一部分。
